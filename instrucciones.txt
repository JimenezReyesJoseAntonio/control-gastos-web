# App Web de Control de Gastos a Meses - Mis Compras
## 1. Resumen del Proyecto
Crear una aplicación web sencilla, responsive y en español, para llevar control de compras personales hechas con tarjeta de crédito / débito. Cada usuario entra solo con Nombre + Contraseña (sin correo). Cada usuario ve ÚNICAMENTE sus propios datos. Los datos nunca se mezclan entre usuarios. La app debe permitir registrar compras, dividirlas a meses, marcar pagos mensuales y ver totales por mes y por año.
## 2. Stack Tecnológico
Frontend: Vue 3 + Vite + Vue Router + Pinia. UI: Tailwind CSS. Diseño limpio, estilo fintech, modo claro. Colores principales: morado / verde para pagado, rojo para pendiente. Backend / Base de datos / Auth: Supabase (Postgres + Auth + RLS). Librería de Supabase: @supabase/supabase-js. Manejo de fechas: date-fns. No usar: Firebase, correo electrónico, verificación por email, OAuth.
## 3. Autenticación - Requisitos Clave
Registro: Campos: Solo Nombre de usuario y Contraseña. No pedir correo, teléfono, nombre real. Al registrarse, crear usuario en Supabase Auth. Para cumplir con Supabase Auth que pide email, generar un email interno falso: {nombre_usuario_limpio}@miscompras.app. El usuario NUNCA ve este email. Guardar también en tabla profiles: id, username, created_at. Validaciones: nombre mínimo 3 caracteres, sin espacios, solo letras, números, _ y -. Contraseña mínimo 4 caracteres. Si el nombre ya existe, mostrar error: "Ese nombre ya está en uso". Login: Campos: Nombre de usuario + Contraseña. Convertir nombre a email interno y hacer signInWithPassword. Si falla, mostrar: "Nombre o contraseña incorrectos". Al entrar, guardar sesión en Supabase y redirigir a /dashboard. Botón Cerrar Sesión en todas las vistas privadas. Seguridad: Activar Row Level Security (RLS) en TODAS las tablas. TODAS las consultas deben filtrar por user_id = auth.uid(). Nunca mostrar datos de otro usuario. Contraseñas solo con hash de Supabase Auth, nunca en texto plano.
## 4. Base de Datos en Supabase - SQL a Crear
Tabla profiles: create table profiles (id uuid primary key references auth.users(id) on delete cascade, username text unique not null, created_at timestamptz default now()); Tabla tarjetas: create table tarjetas (id bigint generated always as identity primary key, user_id uuid not null references auth.users(id) on delete cascade, nombre text not null, tipo text not null default 'credito', fecha_corte int, fecha_limite_pago int, created_at timestamptz default now()); Tabla compras: create table compras (id bigint generated always as identity primary key, user_id uuid not null references auth.users(id) on delete cascade, tarjeta_id bigint references tarjetas(id) on delete set null, que_compre text not null, tienda text, fecha_compra date not null default current_date, total numeric(12,2) not null, meses int not null default 1, mensualidad numeric(12,2) not null, mes_inicio date not null, mes_fin date not null, estatus text not null default 'activa', nota text, created_at timestamptz default now()); Tabla pagos: create table pagos (id bigint generated always as identity primary key, user_id uuid not null references auth.users(id) on delete cascade, compra_id bigint not null references compras(id) on delete cascade, mes date not null, monto numeric(12,2) not null, pagado boolean not null default false, fecha_pago date, created_at timestamptz default now(), unique(compra_id, mes)); Políticas RLS: alter table tarjetas enable row level security; alter table compras enable row level security; alter table pagos enable row level security; alter table profiles enable row level security; create policy "Usuarios ven solo lo suyo" on tarjetas for all using (auth.uid() = user_id) with check (auth.uid() = user_id); create policy "Usuarios ven solo lo suyo" on compras for all using (auth.uid() = user_id) with check (auth.uid() = user_id); create policy "Usuarios ven solo lo suyo" on pagos for all using (auth.uid() = user_id) with check (auth.uid() = user_id); create policy "Usuarios ven solo lo suyo" on profiles for all using (auth.uid() = id) with check (auth.uid() = id);
## 5. Lógica de Negocio - MUY IMPORTANTE
Al crear una compra: 1. Calcular mensualidad = total / meses redondeado a 2 decimales. 2. Calcular mes_fin = mes_inicio + (meses - 1) meses. 3. Insertar compra en tabla compras. 4. Generar automáticamente N filas en tabla pagos, una por cada mes. Ejemplo: Total 7800, 12 meses, inicio Dic 2026 -> genera pagos Dic 2026, Ene 2027... Nov 2027, cada uno de 650, pagado = false. 5. Si meses = 1, generar solo 1 pago para ese mes. Al marcar un pago como pagado: Cambiar pagado = true y poner fecha_pago = hoy. Si se desmarca, poner pagado = false y fecha_pago = null. Después de marcar, verificar si TODOS los pagos de esa compra están pagados. Si sí, cambiar estatus de la compra a liquidada. Si no, dejar en activa. Al eliminar una compra: Borrar también sus pagos (on delete cascade). Cálculos del Dashboard: Debes este mes = Suma de monto de pagos donde mes = mes actual y pagado = false. Ya pagaste este mes = Suma de monto donde mes = mes actual y pagado = true. Te falta este mes = Debes este mes. Total deuda general = Suma de todos los pagos donde pagado = false. Total pagado general = Suma de todos los pagos donde pagado = true. Total gastado en compras = Suma de total de compras. Resumen por Mes / Año: Selector de mes (input type=month) y selector de año. Mostrar: Total a pagar ese mes, Total ya pagado, Total pendiente, Lista de pagos de ese mes con nombre de compra, tarjeta y estado. Para año: Sumar los 12 meses y mostrar total anual pagado y pendiente, más gráfica de barras por mes.
## 6. Pantallas / Rutas Vue
Rutas Públicas: /login - LoginView.vue, /registro - RegisterView.vue. Rutas Privadas (requieren sesión, usar navigation guard): /dashboard - DashboardView.vue - Resumen, /compras - ComprasView.vue - Lista de compras, /compras/nueva - NuevaCompraView.vue - Formulario, /compras/:id - DetalleCompraView.vue - Ver pagos de esa compra, /resumen - ResumenView.vue - Por mes y por año, /tarjetas - TarjetasView.vue - CRUD de tarjetas. Componentes Reutilizables: AppHeader.vue - Saludo "Hola, {username}", botón Cerrar Sesión, CompraCard.vue - Tarjeta con nombre, tienda, total, avance Ej: 3/12, barra de progreso, mensualidad, botón Marcar pago próximo, PagoRow.vue - Fila de pago con mes, monto, checkbox pagado, ResumenCard.vue - Tarjeta de total, ModalConfirmar.vue - Para eliminar.
## 7. Detalle de Cada Pantalla
7.1 Login / Registro: Diseño centrado, card blanca, logo "Mis Compras". Input Nombre de usuario, Input Contraseña (type=password). Botón grande "Entrar" / "Crear cuenta". Link para cambiar entre login y registro. Mostrar error en rojo si falla. 7.2 Dashboard: Título: "Hola, {username}". 4 tarjetas arriba: 1. Debes este mes: $X 2. Ya pagaste este mes: $X 3. Te falta por pagar (total): $X 4. Total gastado en compras: $X. Botón grande: "+ Agregar Compra". Sección: "Pagos de este mes" - Lista de pagos pendientes y pagados de este mes con checkbox para marcar. Sección: "Próximos pagos" - Siguiente mes. Sección: "Mis compras activas" - Top 5 con barra de avance. 7.3 Nueva Compra: Formulario con: Qué compraste (text, obligatorio), Tienda (text, opcional), Fecha de compra (date, default hoy), Total (number, obligatorio, >0), Tarjeta (select de tabla tarjetas + botón "+ Nueva tarjeta"), Tipo de pago: Radio [1 solo pago] [A meses], Si es A meses: Input Meses (number, Ej: 3, 6, 12, 18), Mes que empieza a pagar (month, default mes siguiente), Nota (textarea, opcional), Vista previa en vivo: "Vas a pagar $X al mes, de Dic 2026 a Nov 2027", Botón Guardar -> Genera pagos y va a /compras. 7.4 Mis Compras: Filtro: Todas / Activas / Liquidadas + Buscador por nombre. Lista de CompraCard. Cada card muestra: Nombre, Tienda, Tarjeta (Nu, BBVA), Total, Mensualidad, Avance Ej: 3/12, Barra de progreso %, Fecha fin, Botones: Ver detalle, Marcar siguiente pago, Eliminar. Al hacer clic en Marcar pago: Marca el primer pago pendiente de esa compra. 7.5 Detalle de Compra: Datos de la compra arriba. Lista completa de pagos: Mes, Monto, Estado Pagado/Pendiente, Checkbox. Botón Marcar todos como pagados / Desmarcar. Botón Eliminar compra. 7.6 Resumen por Mes / Año: Tabs: Por Mes | Por Año. Por Mes: Input month, muestra 3 totales y lista de pagos. Por Año: Input number año, muestra total anual, gráfica de barras con 12 meses (usar Chart.js o ECharts, simple). Botón Exportar a CSV opcional. 7.7 Tarjetas: Lista de tarjetas del usuario. Formulario para agregar: Nombre (Nu, BBVA), Tipo (Crédito/Débito/Efectivo), Fecha corte, Fecha límite. Editar y Eliminar.
## 8. Manejo de Estado con Pinia
useAuthStore: user, username, login(), register(), logout(), checkSession(). useComprasStore: compras, pagos, cargarCompras(), crearCompra(), marcarPago(), eliminarCompra(), totalesPorMes(). useTarjetasStore: tarjetas, cargarTarjetas(), crearTarjeta().
## 9. Variables de Entorno
Archivo .env: VITE_SUPABASE_URL=tu_url, VITE_SUPABASE_ANON_KEY=tu_anon_key. Crear archivo src/lib/supabase.js que exporte cliente supabase.
## 10. Estilo y UX
Mobile-first, debe verse bien en celular. Usar Tailwind, cards con sombra suave, bordes redondeados. Formato de dinero en MXN: $1,234.56. Formato de fechas en español: "Dic 2026". Al marcar pago, animación rápida y actualización inmediata sin recargar página. Mensajes de éxito con toast: "Pago marcado", "Compra guardada". No usar modales complicados, usar pantallas simples.
## 11. Qué NO debe hacer la app
No pedir correo. No pedir verificación por email. No conectar bancos. No usar datos de otros usuarios. No permitir ver compras sin estar logueado. Si entra a /dashboard sin sesión, redirigir a /login.
## 12. Datos de Prueba para Desarrollo
Crear usuario de prueba: antonio / 1234. Tarjetas: Nu (Crédito), BBVA (Crédito). Compras de ejemplo: 1. Pantalla - Liverpool - $7,800 - Nu - 12 meses - Inicio Dic 2026. 2. Tenis - Nike - $1,500 - BBVA - 1 pago - Nov 2026. 3. Celular - $12,000 - Nu - 18 meses - Inicio Ene 2027.
